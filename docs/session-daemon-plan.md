# nightcrow 세션 데몬 — 구현 계획

> **상태: A~F 완료, G는 절반(폴링 중복 제거는 했고, TUI가 데몬 스냅샷을 구독하는 것은 안 했다).** E에서 확정된 설계는
> `docs/architecture.md`("TerminalBackend Trait", "세션 공유")로 이관했다. 이 문서는
> **왜 그렇게 갔는지**와 **어떤 순서로 갔는지**를 담는다.
>
> 계획과 달라진 점:
> - **B단계는 C·D에 흡수했다.** 데몬이 없는 상태의 `attach` 별칭과 `application/`을
>   `client/`로 미리 옮기는 것은 아직 클라이언트가 아닌 것에 클라이언트 이름을 붙이는
>   선반영이라, 실제 소비자가 생기는 시점에 만들기로 했다.
> - **단일 인스턴스 판정은 flock이다** (계획에는 "stale 소켓 정리"로만 적혀 있었다).
>   남은 소켓에 connect해서 살아 있는 데몬인지 보려 했으나, macOS에서는 리스너가 닫힌
>   소켓에도 connect가 성공할 수 있어 판정이 성립하지 않았다(테스트가 세 번에 한 번꼴로
>   실패). `flock`은 `kill -9`에도 커널이 해제하므로 정확하다.
> - **`-d`는 F로 미뤘다.** attach 클라이언트가 없는 동안에는 쓸 일이 없고, F에서
>   `nightcrow`가 데몬이 될 때 기동 방식을 한 번에 정리하는 편이 낫다.
> - **순서를 D → F → E로 바꿨다.** F를 E 뒤에 두면 E 내내 `TerminalState`가 로컬 PTY와
>   원격 hub 양쪽을 다뤄야 한다. F를 먼저 하면 E는 최종 형태 하나만 보고 작업한다.
>   대가는 E가 끝날 때까지 detach가 터미널을 죽인다는 것인데, 그건 지금도 없는 기능이라
>   잃는 것이 아니라 아직 얻지 못한 것이다.

## 1. 목표

nightcrow를 **세션 데몬 하나 + 프론트엔드 N개** 구조로 바꾼다.

- 데몬이 세션의 단일 소스다: 저장소 집합·순서, 활성 프로젝트, 터미널 pane과 그
  PTY, `~/.nightcrow/workspace.json`.
- TUI는 Unix 소켓으로 붙는 클라이언트(`nightcrow attach`), 브라우저는 웹으로 붙는
  클라이언트다. **둘은 같은 터미널 세션을 본다** — 지금처럼 각자 PTY를 따로 띄우지
  않는다.
- 각 클라이언트는 자기 디스플레이 종류와 크기에 맞게 **스스로 렌더한다**. 화면을
  반사받는 것이 아니다.
- TUI를 닫아도 세션은 산다. 세션 종료는 데몬을 직접 끄는 일이다.

## 2. 제약

- **async 런타임 무도입** — 동기 스레드 모델을 유지한다.
- **git 온디맨드 읽기는 TUI 로컬 유지** — diff/file/tree/log는 지금처럼 UI 스레드에서
  동기로 읽는다. 3절 참고.
- **새 프로토콜을 발명하지 않는다** — 뷰어가 이미 쓰는 메시지 타입을 전송만 바꿔
  재사용한다.
- **단일 프로세스 모드 제거, 웹 미러 제거.**
- 각 커밋이 빌드·테스트를 통과하고 **쓸 수 있는 상태**여야 한다. 중간에 TUI를 못 쓰는
  기간이 없도록 단계를 배치한다.

## 3. 범위에서 뺀 것: 원격 attach

다른 머신의 데몬에 TUI로 붙는 것은 목표가 아니다. 그래서 git 데이터를 프로토콜로
옮기지 않는다.

옮기려면 `app/`의 "선택이 바뀌면 그 자리에서 동기로 읽는다"는 전제를 전부 pending
상태를 갖는 비동기 요청으로 뒤집어야 하는데(`diff_load`, `commit_log_fetch`, `tree`,
`file_view_load`, `snapshot_io`), 로컬에서는 양쪽이 같은 디스크를 읽어 1초 안에
수렴하므로 사용자에게 보이는 이득이 거의 없다. 비용은 이 프로젝트에서 제일 크다.

**남는 흠 — 절반 걷었다**: TUI와 데몬이 각각 `SnapshotChannel`을 돌리므로 둘이 동시에
볼 때는 저장소당 `git status`가 2배다. 다만 데몬은 **구독자가 없으면 순회를 멈추므로**
(8절 G) 브라우저만, 또는 TUI만 있는 세션에서는 중복이 없다. 남은 절반은 온디맨드
읽기가 아니라 주기적인 부분만 공유하는 일이고, 그 대가는 G에 적었다.

## 4. 왜 클라이언트 렌더인가

가능한 구조가 둘이었다.

| | 서버 렌더 (미러 확장) | **클라이언트 렌더 (선택)** |
|---|---|---|
| 방식 | 데몬이 ratatui로 한 장 그려 ANSI를 민다 | 데몬은 상태를, 클라이언트가 그린다 |
| 클라이언트 비용 | 수백 줄 | 프론트엔드 하나만큼 |
| 디스플레이별 크기 | **불가** — 그리드가 하나뿐 | 가능 |

"디스플레이 종류·사이즈에 따라 재렌더링"이 목표에 있으므로 서버 렌더는 성립하지
않는다. 그리드가 하나면 모두가 같은 크기를 강제로 공유하게 된다.

그리고 클라이언트 렌더 프로토콜은 **이미 있다** — 뷰어가 쓰는 것이 그것이다. 이
작업은 새 데몬을 만드는 일이 아니라 `nightcrow serve`를 세션 데몬으로 승격시키고
TUI를 그 클라이언트로 돌려세우는 일이다.

미러(`src/web/`)는 이 그림에서 존재 이유가 사라진다. 브라우저가 화면 반사 대신
네이티브 프론트엔드로 같은 세션에 붙기 때문이다. 제거한다.

## 5. 핵심 이음매: `TerminalBackend`

`TerminalBackend` trait이 정확히 필요한 자리에 이미 있다.

```rust
fn create_pane(rows, cols, command) -> Result<PaneId>
fn send_input(id, data);  fn resize(id, rows, cols);  fn destroy_pane(id)
fn drain_events() -> Vec<BackendEvent>   // Output / Exited
```

이것이 뷰어 `TerminalHub`의 `ClientMessage`(Create/Input/Resize/Close/Reorder/Start)와
`ServerMessage`(Created/Exited/Reordered) + 바이너리 출력 프레임에 거의 1:1로
대응한다. `TerminalState`는 이미 `backend: Option<Box<dyn TerminalBackend>>`라 교체
지점이 하나다. 그래서 터미널 공유는 **`PtyBackend` 옆에 `HubBackend`를 하나 더
만드는 일**이 된다.

`PaneEmulator`도 `process(&[u8])`로 raw 바이트를 먹으므로, 입력원이 로컬 PTY reader에서
소켓 스트림으로 바뀔 뿐 그대로 재사용된다. VT 에뮬레이션은 클라이언트가 한다 —
뷰어에서 xterm.js가 서 있는 자리와 같다.

**trait이 한 군데 바뀐다.** pane 생성이 이제 비동기이고, 다른 클라이언트도 pane을
만든다. `create_pane`이 `PaneId`를 즉시 돌려줄 수 없으므로 `BackendEvent::Created`를
추가하고 생성은 fire-and-forget이 된다. `TerminalState.panes`는 로컬 Vec에서 서버
canonical order의 투영이 되고, `swap_active_with`는 `Reorder` 요청이 된다.

## 6. PTY 크기 소유권

PTY는 데이터가 아니라 자식 프로세스와 맺은 계약이다. 자식은 `TIOCGWINSZ`로 들은
폭에 맞춰 출력을 만들므로, 80칸으로 그려진 화면을 200칸으로 다시 그릴 데이터는
어디에도 없다. 따라서 pane의 셀 크기는 **단일 값**이어야 한다.

클라이언트마다 자기 에뮬레이터를 자기 크기로 돌리는 방식은 줄 단위 출력에만
통한다. alternate screen을 쓰는 풀스크린 TUI(Claude Code, Codex, vim)는 커서를 절대
좌표로 움직이므로, 폭이 다른 두 에뮬레이터가 그것을 각자 해석하면 두 화면이 서로
다른 쓰레기로 갈라진다. 그리고 그게 이 앱의 주 용도다.

**정책** — tmux의 `window-size latest`와 같은 모델:

- pane의 PTY 크기 = **현재 소유자 클라이언트가 그 pane에 할당한 크기**
- 소유권은 attach 시 자동 이동, 이미 붙어 있는 상태에서는 키로 명시적 탈취
- 소유자가 표시하지 않는 pane, 그리고 전원 detach 상태에서는 **마지막 크기 유지**
- 비소유 클라이언트: 그리드가 자기 영역보다 작으면 여백, 크면 잘라서 보여준다

입력마다 소유권을 옮기는 대안은 기각했다. 폰으로 잠깐 확인하는 흔한 동작이 곧바로
전체 repaint를 유발해, 제일 가벼운 행동이 제일 비싼 행동이 된다.

이 정책의 부수 효과로 **비소유 클라이언트가 곧 관전자**가 되므로 별도의 관전 모드를
만들 필요가 없다.

## 7. 공유/비공유 경계

"모두가 동일 소스"를 문자 그대로 다 적용하면 브라우저에서 커서를 내릴 때 TUI 커서도
같이 내려간다. 그러면 디스플레이별 렌더링이 의미를 잃는다.

- **공유(데몬 소유)**: 저장소 집합과 순서, 활성 프로젝트, 터미널 pane 집합·내용·
  순서·크기
- **클라이언트별**: 뷰 모드(status/log/tree), 커서·선택·스크롤, 포커스, fullscreen,
  검색/필터 텍스트, accent

**accent는 공유 목록에서 뺐다** (초안에는 있었다). 세션 사실이 아니라 표시 취향이고,
무엇보다 **TUI의 accent는 저장소별**이다 — 색으로 탭을 구별하는 것이 그 기능의 목적이라
세션 전역 값 하나로 만들면 그것이 사라진다. 뷰어가 accent를 공유하는 것은 자기 표면
안에서(한 chrome, 여러 기기)이지 세션 상태로서가 아니다.

**활성 프로젝트는 공유로 확정했다** (D 단계에서는 클라이언트별로 구현돼 있었고, 뷰어도
같은 판단이 코드에 박혀 있었다 — `resolveActiveRepo`). 대가는 알고 택했다: 폰에서 탭을
바꾸면 노트북 화면도 옮겨간다. 대신 "브라우저와 TUI가 서로 다른 프로젝트를 보여주는데
둘 다 정상"인 상태가 없어진다. 아무도 고른 적 없으면 첫 저장소로 떨어진다 — 답이 없으면
클라이언트마다 각자 고르고, 그게 없애려던 그 분기다.

## 8. 단계

순서는 **A → C → D → F → E → G**다. F(커맨드 표면 전환)는 되돌리기 어렵고 그 시점까지
TUI에 닿는 유일한 길을 지워서는 안 되므로 D 뒤에 오지만, E 앞에 둔다 — 그래야 E가
터미널 백엔드 경로 하나만 상대한다.

**A. 미러 제거**
`src/web/{protocol,server,frontend}` 삭제, `event_loop`의 broadcast·`drain_input`·
`dispatch_web_event` 제거, `WebSurfaces`/`start_web_if_enabled` 정리, `[web_mirror]`
설정 제거. `web/common/`은 뷰어가 쓰므로 유지. `deny_unknown_fields`를 쓰지 않으므로
기존 config에 남은 `[web_mirror]` 섹션은 무시된다.

**B. `nightcrow attach` 신설 (동작 불변)**
클라이언트 코드가 들어갈 자리를 만들고 `TerminalGuard`와 이벤트 루프를 옮긴다.
데몬이 아직 없으므로 지금의 TUI를 그대로 띄우는 별칭으로 시작한다. 순수 이동.

**C. 데몬 골격 — 완료**
UDS 리스너(`~/.nightcrow/daemon.sock`, 0600) + `flock` 단일 인스턴스 락. 프레이밍은
길이 프리픽스 + kind 바이트(control JSON / terminal raw). 세션 조작을 HTTP 래퍼에서
분리해(`web/viewer/session.rs`) 두 전송이 같은 함수를 호출한다. SIGINT/SIGTERM
graceful shutdown — 신호 **등록과 대기를 분리**해, 저장소를 열고 startup 셸을 띄우는
동안 도착한 신호도 잃지 않는다.

**연결은 요청/응답이 아니다.** 세션이 공유되므로 데몬이 먼저 말한다 — 브라우저에서 연
저장소가 아무것도 묻지 않은 TUI에 닿아야 한다. 그래서 클라이언트마다 큐와 그것을
비우는 writer 스레드를 두고, **상태 변경은 브로드캐스트**한다. 거절은 물어본
클라이언트에게만 간다(모든 TUI가 남의 오타로 에러를 번쩍이면 안 된다). 이 모양은
E의 터미널 출력이 요구하는 것과 같아서 그때 버려지지 않는다.

**D. attach 클라이언트를 데몬에 연결 (저장소 집합) — 완료**
클라이언트 연결부(`daemon/client.rs`) — 핸드셰이크 후 데몬이 말하는 모든 것을
큐에 쌓고, 호출자가 렌더 틱마다 비운다(소켓에서 블록하지 않는다). 대기에 상한을 두는
곳은 핸드셰이크뿐이다: 그 뒤로는 조용한 세션이 정상이라 타임아웃이 있으면 유휴를
끊김으로 지어낸다.

`nightcrow attach`가 이 연결 위에 선다. 탭 열기/닫기/순서는 로컬 변경이 아니라
요청+반영이고, `workspace.json`의 저장소 목록은 데몬 소유다 — 클라이언트는 자기 뷰
상태(선택·스크롤)만 같은 파일에 되쓴다.

**E. 터미널 세션 공유 — 핵심 (완료)**

*끝난 것*

- **데몬이 터미널을 중계한다.** attach하면 열린 모든 저장소의 허브(브라우저가 쓰는 그
  허브)에 구독되고, 출력은 저장소·pane 태그가 붙은 바이너리 프레임으로, 제어 메시지는
  허브의 타입 그대로 전달된다. 화면에 보이는 저장소만이 아니라 **전부** 구독한다 —
  읽기를 멈춘 pane은 자기 스크롤백(바이트 상한)보다 뒤처진다. 대가는 클라이언트×저장소당
  스레드 하나.
- **pane 생성이 비동기가 됐다.** `create_pane`은 "요청"이고 pane은
  `BackendEvent::Created`로 도착한다. 공유 세션을 서빙하는 백엔드는 id를 즉석에서
  답할 수 없고(id는 PTY가 실제로 사는 곳에서 나온다), 남이 연 pane도 같은 경로로
  와야 하기 때문이다. 이벤트가 **`requested`를 실어** 내가 연 pane만 포커스를 가져간다 —
  어느 pane을 보고 있는지는 클라이언트 각자의 일이다. 제목도 같은 규칙으로 큐에 대기했다
  도착 시 적용된다.
- `PtyBackend`는 `open_pane`으로 직답을 유지한다. 터미널 허브가 trait이 아니라 구체
  타입을 소유하고, 만든 즉시 등록해야 하기 때문이다.
- **`HubBackend`가 붙었다.** `TerminalBackend`를 데몬 소켓 위에 얹은 것으로, 저장소당
  하나이고 `DaemonClient`의 연결을 공유한다. 수신 스레드가 저장소별 inbox로 라우팅하고
  (`Mutex<HashMap<repo, VecDeque<..>>>`), 각 백엔드가 자기 것만 드레인한다. 쓰기는
  `Arc<Mutex<UnixStream>>`. inbox는 **도착 시점에 생긴다** — attach하면 데몬이 곧바로
  스트리밍을 시작하므로 "이 저장소가 있다"는 통보보다 pane 리플레이가 먼저 올 수 있고,
  리플레이는 한 번뿐이다.
- **`requested`는 id 비교로 답했다.** 허브 `Created`에 `client`를 싣고, 데몬이 릴레이할 때
  **attach 소켓의 id 공간으로 바꿔 준다**(클라이언트는 저장소별 허브 id를 알 수 없다).
  hello 응답이 그 id를 알려준다. 필드는 없을 때 직렬화에서 빠지므로 브라우저 프레임은
  바이트 단위로 그대로다. startup pane과 리플레이 pane은 요청자가 없다 — 세션의 것이지
  마지막에 붙은 클라이언트의 것이 아니다.
- **startup command는 데몬만 실행한다.** 클라이언트는 허브의 사이징 제안에 **빈 목록으로**
  답한다. 제안은 첫 프레임 전에 오므로 실제로 측정한 것이 없고, 허브 기본값으로 열린 뒤
  첫 레이아웃이 교정한다(로컬 PTY 시절과 같은 repaint 한 번). `ensure_initial_terminal`은
  삭제했다 — 로컬 백엔드 경로가 프로덕션에 남아 있지 않다.
- **복원 세션의 터미널 절반이 pane을 기다린다.** 포커스·활성 pane·fullscreen은 pane이
  없으면 가리킬 대상이 없으므로 `pending_terminal`에 담아 두고 첫 pane 도착 시 적용한다.
  신규 실행의 "터미널로 포커스" 기본값도 같은 자리에 담기므로 둘이 첫 프레임을 두고
  다투지 않는다.
- **터미널 거절은 pane inbox가 아니라 notice 큐로 간다.** 그리고 앞에 있는 탭이 아니라
  **그 저장소의 탭**에 뜬다.
- **뒤처진 클라이언트는 프레임을 버리는 대신 끊는다.** 이 큐로 pane 출력이 흐르게 된
  이상 한 프레임 유실은 이후 전부를 깨뜨린다(허브가 한 단 안쪽에서 하는 것과 같은 선택).

- **크기 소유권을 허브가 중재한다** (6절). 접속이 곧 소유권 이전(tmux `window-size
  latest`), 이미 붙어 있으면 `claim_size`로 명시적 탈취(TUI는 `<prefix> z`, 뷰어는
  "fit to this screen" 버튼). 소유자가 떠나면 남은 중 가장 최근 클라이언트에게,
  아무도 없으면 마지막 크기 유지. 비소유자의 resize는 버려지고, **실제 적용된 크기를
  브로드캐스트**한다(`Resized`) — 관전자의 에뮬레이터도 자식이 감는 곳에서 감아야 한다.
  소유자도 그것을 읽지만(clamp된 요청을 그렇게 알게 된다) "내가 요청한 값" 기록은
  유지한다. 그러지 않으면 매 프레임 같은 clamp를 다시 요청한다.
- **영역과 그리드가 다른 경우는 렌더 경로가 이미 clamp로 처리한다** — 작으면 여백,
  크면 잘라냄. 관전자가 실제 상태가 된 지금 테스트로 고정했다.
- **활성 프로젝트가 공유가 됐다** (7절). 세션이 이름을 대고 모든 클라이언트가 따라간다.
  집합과 함께 실려 온다 — 저장소를 열면 그것이 활성이 되므로 둘은 같이 바뀌고, 따로
  배우면 탭 목록만 있고 어느 탭을 보여줄지 모르는 상태가 생긴다.
- **데몬이 세션을 감시한다.** 브라우저를 통한 변경은 attach 소켓의 아무것도 깨우지
  않으므로, 틱마다 세션을 다시 읽어 마지막으로 알린 것과 다르면 브로드캐스트한다.
  알림(callback)이 아니라 관측인 이유: 알림은 나중에 추가된 mutation이 빼먹을 수 있고
  그 실패가 정확히 이 버그로 다시 나타난다. attach 클라이언트의 요청은 watcher를
  즉시 깨우므로(`Nudge`) 키 입력이 폴링 간격을 기다리지 않는다.

- **pane 순서가 세션의 것이 됐다.** swap은 요청이고 `Reordered`가 오면 적용된다 — 브라우저에서
  드래그한 순서도 같은 경로로 온다. 맹목적으로 적용하지 않고 reconcile한다: 아직 adopt하지 않은
  id는 건너뛰고 언급되지 않은 pane은 자기 자리를 지킨다(create/exit와 경합해도 적용된다).
  포커스는 슬롯이 아니라 **보고 있던 pane**을 따라간다 — pane을 옮기면서도 계속 보는 것이
  swap의 목적이다.
- **스크롤백 깊이를 실측했다**(10절 1번 해소). 평범한 출력에서는 리플레이가 클라이언트의 1000줄을
  다 채운다. 줄당 ~262바이트를 넘으면(토큰마다 색을 바꾸는 하이라이팅) 못 채운다 — 경계 양쪽을
  테스트로 고정하고 상한은 바꾸지 않았다. 거기 닿는 출력은 대부분 텍스트가 아니라 repaint
  시퀀스이고, 부족분은 1000줄 중 수백 줄이며, 상한은 저장소×pane마다 지불된다.

E는 여기서 끝났다.

**F. 커맨드 표면 전환 — 완료**
`nightcrow` = 데몬(포그라운드 기본, `-d`로 백그라운드), `serve`와 단일 프로세스 TUI
경로 삭제, `[web_viewer] enabled` 토글 제거. TUI의 quit은 detach. 로그는 홈 기준으로
옮겨 데몬도 로그를 남기고, 어느 프로세스도 저장소 안에 쓰지 않는다.

**`--repo`는 남기지 않고 지웠다.** 같은 이름이 자리마다 다른 뜻이었다 — TUI에서는
기억된 목록을 *대체*하고, 데몬과 attach에서는 *추가*했다. 여러 클라이언트가 공유하는
세션에서 저장소를 여는 자리는 안쪽 하나뿐이라(다른 클라이언트가 결과를 보는 유일한
경로다), 둘 중 하나로 통일하는 대신 없앴다. 밖에서 세션을 미리 채우는 요구가 생기면
argv가 아니라 config에 둔다 — 이 시점의 데몬은 서비스 매니저가 띄우고, 거기엔 인자를
타이핑하는 사람이 없다.

**`-d`는 fork가 아니라 재exec이다.** 스레드가 도는 프로세스에서 fork하면 자식은 스레드
하나와 임의 상태의 락들을 물려받는다 — 데몬화 크레이트들이 조심스러워하는 것이 정확히
그것이다. 새 사본을 exec하면 물려받을 상태가 없다. 자식은 `setsid`로 자기 세션을 가져서
띄운 터미널을 닫아도 SIGHUP을 받지 않는다.

**G. (선택) status 폴링 공유 — 절반 완료**
*한 것*: **아무도 안 보는 저장소는 걷지 않는다.** 데몬의 스냅샷 워커는 구독자가 없으면 순회를 멈추고,
첫 구독자에게는 그 자리에서 한 번 읽어 답한다(꺼져 있던 동안의 값은 낡은 것이 아니라 틀린 화면이다).
브라우저만 열려 있거나 TUI만 붙어 있는 세션에서는 중복이 완전히 사라진다.

*안 한 것*: 데몬의 스냅샷을 TUI가 **구독**하는 것. 남는 중복은 브라우저와 터미널이 동시에 볼 때뿐이고,
그때는 양쪽이 정말로 그 데이터를 원한다. 닫으려면 주기적 git 데이터를 attach 프로토콜에 올리고
(3절이 온디맨드 읽기에 대해 피한 그것) TUI가 자기 뷰를 만드는 두 번째 경로를 갖게 된다 — 이득이
보이지 않는 지점에서 값이 비싸다.

## 10. 미결

1. **스크롤백 깊이 — 해소.** 실측: 평범한 출력은 1000줄을 다 채우고, 줄당 ~262바이트를
   넘는 escape-heavy 출력은 그보다 얕다. 상한은 그대로 두고 경계를 테스트로 고정했다
   (`terminal/tests/scrollback_depth.rs`).
2. **새 의존성 — 확정.** `signal-hook` 0.4(SIGTERM 처리; `ctrlc`는 SIGINT만 다룬다.
   2억+ 다운로드, 2026-04 릴리스, MIT/Apache-2.0, async 런타임 불필요)와 `libc`(단일
   인스턴스 락의 `flock` — std가 노출하지 않는 유일한 호출. 이미 20여 크레이트를 통해
   트리에 있어 직접 이름만 붙인 것). 데몬화 크레이트는 **채택하지 않는다** — 표준이
   없이 파편화돼 있고(daemonize/daemonize2/daemonizr/fork), `-d`는 재exec +
   `setsid`로 F에서 처리한다. 재exec은 스레드가 도는 프로세스에서 fork하는 고전적
   함정도 함께 피한다.
3. **입력 프레임 — 확정: 문자열 그대로 쓴다.** 클라이언트가 pane에 보내는 것은 전부
   UTF-8이다 — 키 인코딩(ASCII 제어 바이트 또는 문자의 UTF-8), 붙여넣기 텍스트,
   에뮬레이터의 터미널 질의 응답. 그래서 뷰어의 `Input { data: String }`이 무손실로
   나른다. 그 밖의 바이트는 프레임 종류를 늘릴 이유가 아니라 이쪽 버그이므로 에러로
   보고한다(출력은 반대로 바이너리 프레임이다 — PTY 바이트는 UTF-8 보장이 없다).
4. **세션은 하나** — 사용자당 데몬 하나를 전제한다. named session은 넣지 않는다.
5. **데몬이 죽었을 때 — 확정: 알리고 나간다.** 재연결은 넣지 않았다. 연결이 끊기면 TUI가
   alternate screen을 정상적으로 벗고 이유를 한 줄 출력하며 비정상 종료 코드로 나간다.
   메시지는 "세션이 사라졌다"가 아니다 — 데몬이 살아 있는데 이 연결만 끊긴 경우(뒤처진
   클라이언트를 데몬이 끊는 경로)가 있으므로, 확실한 것만 말하고 재attach를 권한다.
   뷰 상태는 어느 경로로 끝나든 되쓴다. 재연결을 넣으려면 연결을 재접속 가능한 채널로
   바꾸고(스트림 교체·id 공유) 재접속 시 탭마다 pane을 버리고 리플레이를 다시 받아야
   한다(그러지 않으면 스크롤백이 에뮬레이터에 두 번 들어간다) — 지금 설계를 막지 않으므로
   필요해지면 그때 올린다.
